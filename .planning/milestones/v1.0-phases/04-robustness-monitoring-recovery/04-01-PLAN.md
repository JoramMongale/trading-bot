# 04-01 — Robustness: reconnect, weekend guard, market closures, trade ledger

**Status:** COMPLETE — verified 2026-08-27 (24 new tests; full suite 404 passed + 2 skipped; the 1 dashboard failure is pre-existing environmental)
**Depends on:** Phase 1 (strategy core) + Phase 2 (live execution) — both complete
**Scope:** Phase 3 of the roadmap — a bot you can leave running. Detect and
recover from terminal disconnects, refuse to open gold positions that would
sit through the weekend gap, survive extended market closures, and give the
operator a single trade ledger spanning backtest + live/demo runs.

## Goal

The engine already never crashes on a broker failure — `poll_once` returns
`bar_fetch_failed` and the loop carries on. But a bot that is alive and *never
reconnects* is a bot that has quietly stopped trading: the terminal drops, every
poll returns an empty frame, the decision log stays fresh (so nothing looks
wrong), and there is no mechanism that ever re-establishes the connection. This
plan closes that class of failure and the three related gaps below.

1. **Reconnect after a disconnect.** After N consecutive failed polls, tear
   down and re-establish the broker connection (with backoff). The loop stays
   the single source of truth; the engine and adapters only report
   availability. On reconnect the engine's dedup state must survive so a stale
   bar from before the drop is not re-traded (the one-trade guard already holds
   the slot, but the `_last_bar_time` boundary must not be lost either).
2. **Weekend guard.** Gold is shut Friday 21:00 → Sunday 21:00 UTC and a
   broker-side stop cannot protect a Sunday opening gap. The bot currently
   relies on external scheduled tasks to stop it on Friday; the guard makes it
   *self-imposed* in code so a late or missed task cannot leave it opening a
   fresh position into the close. Config: `[live] weekend_stop_hour` (UTC, hour
   of the bar clock after which new entries are refused on Friday) and
   `[live] weekend_resume_hour` (UTC, hour on Sunday at which entries resume).
   Defaults off, so nothing changes unless enabled.
3. **Market-closure survival.** Bars stop arriving; `poll_once` must keep
   returning `bar_check new_bar=False` and resume detection the moment bars
   resume, without false `bar_fetch_failed` spam or a crashed loop.
4. **Trade ledger.** `scripts/trade_ledger.py`: one read-only command that
   merges the backtest `output/trades.csv` with live/demo `order_placed` lines
   from the decision logs and the `trade_closed` lines from `watch_closes.py`
   into a single CSV/printout — entry, SL, TP, exit, R. This is the "review a
   full trade ledger covering backtest and live/demo runs" criterion.

## Design

### 1. Reconnect (`[live] reconnect_after`, `[live] reconnect_backoff`)

- `LiveConfig`: add `reconnect_after: int = 3` and `reconnect_backoff: float = 30.0`
  (seconds). 0 disables reconnection.
- `cli._run_live` loop: track a consecutive-failure counter. `bar_fetch_failed`
  increments it; any other event resets it. When the counter reaches
  `reconnect_after`, call `broker.disconnect()` then `broker.connect()` (the
  ABC already has both), log `event=reconnected` or `event=reconnect_failed`,
  and on failure sleep `reconnect_backoff` before the next poll attempt. Reset
  the counter on a successful poll or a successful reconnect.
- `LiveEngine` keeps its `_last_bar_time` across reconnect — a stale bar from
  before the drop is ≤ the last seen time, so the dedup boundary is preserved
  and nothing re-arms.
- Dry-run is unaffected: SimulatedBroker is always connected, so the counter
  never trips and `reconnect()` is a no-op path.

### 2. Weekend guard (`[live] weekend_stop_hour`, `[live] weekend_resume_hour`)

- `LiveConfig`: `weekend_stop_hour: int = 0` (0 = disabled),
  `weekend_resume_hour: int = 21` (Sunday UTC, default market reopen).
- Pure helper in `live/engine.py`:

  ```python
  def in_weekend(bar_time, stop_hour=0, resume_hour=21) -> bool
  ```

  `bar_time` is the bar's own clock (broker server time = UTC on Exness), same
  basis as the existing `in_session`. Returns True when the bar is inside the
  no-new-entries window: after `stop_hour` UTC on Friday through `resume_hour`
  UTC on Sunday.
- Applied in `poll_once` after the session filter and before acting on a setup:
  if a setup fires inside the weekend window, log `setup_skipped reason=weekend`
  and return `order_skipped`. Detection still runs (levels keep building); only
  acting is suppressed — exactly the `in_session` model.
- Only meaningful for gold; BTC (24/7) configs simply leave it off.

### 3. Market closure

No new code path needed beyond what exists: `fetch_rates` already returns the
last closed bars (or an empty frame when the market is closed), `poll_once`
already treats a repeated/absent bar as `bar_check new_bar=False`, and the loop
keeps polling. The plan adds tests that pin this behaviour: a long gap of empty
frames does not crash or spam, and the first bar after the gap is processed
normally (reconnect counter does not fire on empty frames).

### 4. Trade ledger (`scripts/trade_ledger.py`)

Read-only, stdlib-only. Merges:

- `output/trades.csv` (backtest) — `source=backtest`
- `output/live_*.log` `event=order_placed` lines — `source=live`, with the
  entry/SL/TP from the log fields
- `output/closes.log` `event=trade_closed` lines — matched to live entries by
  ticket to attach exit price, exit reason (`how`), and `r` (R multiple)

Output: one `output/ledger.csv` plus a printed summary (counts, win rate, net
R by source). If a live entry has no close line yet, it prints as open. Uses
the same `stops_from_logs` reconstruction idea as `account_report.py`, but
kept self-contained.

## Success criteria

1. `live --mode dry-run --config config/config.toml` still polls cleanly; with a
   broker that starts failing, the loop reconnects and logs
   `reconnected`/`reconnect_failed`, and never exits.
2. `in_weekend` is a pure, tested function; with `weekend_stop_hour` set, a
   setup on a Friday bar after the stop hour is skipped with `reason=weekend`,
   and a Monday setup is not.
3. A market-closure simulation (bars stop, then resume) produces no errors, no
   reconnect churn, and processes the post-gap bar.
4. `scripts/trade_ledger.py` over a sample backtest CSV + sample live/closes
   logs emits a merged CSV with backtest and live rows and correct R values.
5. Full suite green (baseline 380 passed + 2 skipped; the 1 dashboard
   environmental failure is pre-existing and unrelated).

## Risks

- **Reconnect storms.** If the terminal is down for a long time, naively
  retrying `connect()` every poll hammers it. Mitigated by `reconnect_after`
  gating and `reconnect_backoff` sleep between failed reconnects.
- **Reconnecting the wrong terminal.** `MT5Broker.connect()` already verifies
  the attached terminal's path against `[live] terminal_path` and refuses on a
  mismatch — reconnect runs through the same guard, so the failure mode stays
  loud rather than silent.
- **Weekend guard timing.** Bar timestamps are the broker's clock. A bar
  timestamped exactly at the stop hour is refused; the existing Friday close
  (19:00 UTC) is earlier than the 21:00 UTC market shut, so the guard gives
  margin rather than cutting it fine. Documented in config comments.

## What landed

- `[live] reconnect_after` (default 3) / `reconnect_backoff` (default 30.0):
  the CLI loop counts consecutive `bar_fetch_failed` polls (or a poll that
  raised `BrokerUnavailableError`), and once the counter reaches
  `reconnect_after` calls `broker.reconnect()` — new on the `BrokerClient`
  ABC (default disconnect+connect), overridden in `MT5Broker` to drop the
  cached transport first (a dead silicon bridge socket must be rebuilt, not
  re-initialised in place). Reconnect runs the full `connect()` verification
  again (reachable, trade_allowed, correct install path). Logged as
  `reconnect_attempt` / `reconnected` / `reconnect_failed`.
- `MT5Broker.fetch_rates`: a `None` result while the terminal reports
  disconnected now raises `BrokerUnavailableError` instead of returning an
  empty frame — without this the reconnect path would never see a dead
  terminal. A connected terminal returning None is still a normal no-data
  poll (empty frame, no raise), so market closures do not churn reconnects.
- `[live] weekend_stop_hour` (default 0 = off) / `weekend_resume_hour`
  (default 21): pure `in_weekend(bar_time, stop_hour, resume_hour)` helper;
  a setup firing inside the window is logged `setup_skipped reason=weekend`
  and never placed. Enabled for gold in `config/config-cent.toml`
  (stop 19, resume 21); BTC (24/7) stays off.
- `scripts/trade_ledger.py`: read-only merge of `output/trades.csv`
  (backtest) + `output/live_*.log` `order_placed` lines (live) + `output/
  closes.log` `trade_closed` lines joined by ticket → `output/ledger.csv`
  + printed summary. `--once` prints only; `--json` dumps the summary.
- Config validation for all four new keys; tests pin the defaults off/safe.
