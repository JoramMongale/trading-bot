# 03-01 — AI Trading Layer foundation: DeepSeek advisor + deterministic gate

**Status:** ✓ COMPLETE — verified 2026-08-26 (93 new tests, full suite 380 passed + 2 skipped)
**Depends on:** Phase 1 (strategy core) + Phase 2 (live engine) — both complete
**Scope:** The AI-layer foundation, end to end, offline-first. News/sentiment
pipeline and live deployment of AI-augmented trading are follow-ups.

## Goal

Add the non-deterministic half of the hybrid system to the existing
deterministic bot, following the "AI proposes, deterministic code disposes"
model: DeepSeek is consulted for trade reasoning and a daily market-regime
read, and every proposal passes through a pure, deterministic gate before the
existing, battle-tested execution path can act on it.

The deterministic system keeps full authority over risk and execution. The AI
layer is a *filter and a reasoner* over the deterministic setup — it can veto
(no idea, low confidence, disagreeing bias, wider-than-stop invalidation), it
cannot widen a stop or change the order arithmetic.

## Design

```
src/trading_bot/ai/
  schema.py    AIProposal, RegimeAssessment dataclasses + strict JSON parsing
  base.py      AIClient ABC (propose_trade / assess_regime) + AIClientError
  mock.py      MockAIClient (offline, deterministic) + RecordingAIClient (audit)
  deepseek.py  DeepSeekClient — OpenAI-compatible chat/completions via stdlib
  context.py   TradeContext / RegimeContext builders (pure, from bars+levels)
  prompts.py   Render prompts/*.txt templates with a context
  gate.py      evaluate_proposal — pure APPROVED/BLOCKED/REJECTED gate
  engine.py    AIEngine(LiveEngine) — daily regime check + on-setup gate
  backtest.py  run_ai_backtest — replay history, gate each setup, report

prompts/
  trade_idea.txt   setup-reasoning prompt (strict JSON schema)
  regime_check.txt daily regime prompt (strict JSON schema)
```

Two minimal, additive hooks keep backtest and live on one code path (SAFE-01):

1. `backtest/engine.py::run_backtest(..., setup_veto=None)` — a callable
   `(bar, entry, sl, tp) -> reason|None`. A returned reason skips arming the
   setup and emits `setup_skipped` with it. `None` (default) = unchanged.
2. `live/engine.py::LiveEngine.on_setup` calls a `self._ai_gate(...)` hook
   between the dedup/slot guards and the safety gate. Default no-op returns
   `None` (unchanged behavior).

`AIEngine(LiveEngine)` provides `_ai_gate`: builds the trade context, asks
DeepSeek for a proposal, runs the gate, logs `ai_proposal` / `ai_rejected` /
`ai_blocked` and returns the skip event or `None` (proceed to the parent's
placement path).

## Cadence (user decision)

- **On every deterministic setup** — validate the trade idea before execution.
- **Once per day** — a market-regime assessment that can suppress setups for
  the day (e.g. `CHOPPY`/`tradeable=false`).

## Gate rules (pure, deterministic)

An `AIProposal` is accepted only when ALL hold:

1. `bias != NONE` (else REJECTED `no_idea`)
2. `confidence >= [ai] min_confidence` (else BLOCKED `low_confidence`)
3. `bias` agrees with the setup direction when `require_agreement` (else
   BLOCKED `bias_mismatch`)
4. `invalidation_level` (if given) must not widen the stop and must sit on the
   risk side of the trade: for a LONG `sl <= invalidation <= entry`, for a
   SHORT `entry <= invalidation <= sl` (else BLOCKED `invalid_invalidation`)

## Configuration (`[ai]` table, all defaulted)

```toml
[ai]
enabled = false           # opt-in; live/demo execution stays default-off
provider = "mock"         # "mock" (offline) | "deepseek"
model = "deepseek-chat"
api_base = "https://api.deepseek.com"
api_key_env = "DEEPSEEK_API_KEY"   # secret lives in env, never in config
temperature = 0.2
max_tokens = 500
timeout = 30
min_confidence = 70
require_agreement = true
regime_check_daily = true
block_when_choppy = true
record_calls = true       # JSONL audit to output/ai_calls_<log>.jsonl
prompt_dir = "prompts"
```

## Success criteria

1. `python -m trading_bot.cli ai-backtest --config config/config-ai.toml` runs
   offline with the mock provider over historical bars and reports both the
   raw deterministic stats and the AI-gated stats, with every AI decision in
   the decision log (`ai_regime`, `ai_proposal`, `ai_rejected`, `ai_blocked`).
2. A DeepSeek integration with NO hard dependency on the `openai` package:
   stdlib `urllib` against the OpenAI-compatible endpoint, JSON mode, lazy
   import, fake-HTTP tested.
3. `live --mode dry-run --ai` replays one setup through the full path: mock
   proposes → gate approves → deterministic engine places (dry-run no-send).
4. Existing suite stays green: both hooks are no-ops by default, pinned by
   tests that call them explicitly.

## Risks

- **The AI adds no measured edge.** It is a filter; filters narrow the sample
  and can flatter a backtest. The AI-backtest reports the raw-vs-gated
  comparison and this plan makes NO live-account claim. Live wiring stays
  behind `[ai] enabled` + existing SAFE-03.
- **Live regime context is thin** (the fetch window is ~69 M5 bars ≈ 6h).
  Accepted for the foundation; extending the live history window is a follow-up.
- **API cost/latency.** Cadence bounds calls to ~1/setup + 1/day. A failed or
  timed-out call must fail OPEN or CLOSED consistently — decided here: a
  transport failure on the proposal gate fails CLOSED (skip the trade, log);
  a failure on the daily regime check does not block the day (log, continue),
  because the regime is a filter, not a safety device.
