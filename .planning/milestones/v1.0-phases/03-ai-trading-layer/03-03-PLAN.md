<objective>
DuckDB + dbt analytics warehouse: the bot's own artifacts become a queryable
local data platform (user-locked stack: DuckDB + DBT).

Purpose: upgrade.txt Phase 2/5 wants the system to learn from its own
decisions. Today the evidence is spread across CSVs, key=value logs and JSONL
audit files. This plan lands one DuckDB database (data/analytics/trading.duckdb)
that ingests every artifact idempotently, and a dbt project (dbt-duckdb
adapter) that turns the raw tables into marts. Everything downstream — the
dashboard (03-05), news pipeline (03-04), and future analysis — reads these
marts. Nothing leaves the machine; the database is a local analytics file.
Output: warehouse loader + CLI, dbt project with staging+marts, verified
against the real output/ directory.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk artifacts -> DuckDB | Local CSVs/logs/JSONL (bot's own output) cross into the database |
| DuckDB file -> consumers | The .duckdb file is read by later plans (dashboard 03-05, news 03-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | I (malformed/malicious artifact rows) | warehouse/load.py parsers | mitigate | All inputs are the bot's own local files; still, parse defensively (skip unparseable lines with a notice, never raise on a bad row), and staging models drop rows that fail type casts. No SQL is built from file content — fixed statements only. |
| T-04-03-02 | T (SQL injection via filenames/columns) | load.py / dbt models | mitigate | Column names and table names are fixed literals; file content only flows through typed parameters/JSON casts. Never interpolate file content into SQL text. |
| T-04-03-03 | E (DB corruption / partial load) | load.py | mitigate | Loads run per-table MERGE transactions; re-running is idempotent so a failed run is fixed by re-running. The .duckdb file is local and disposable (rebuildable from artifacts). |
| T-04-03-04 | S (secrets in ai_calls JSONL) | raw_ai_calls ingestion | accept | ai_calls contains prompts/responses, no credentials (03-01 design: key lives in env, never in prompts). File is local + gitignored (output/). No new exposure; the dashboard (03-05) reads marts that never expose raw prompt text. |
</threat_model>
