## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Next.js server | The user's own browser hits loopback-bound routes |
| Next.js server -> DuckDB | Read-only queries cross into the analytics database |
| Next.js server -> config TOML | [risk]/[live] tables read from disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-01 | S (credential exposure) | web app env/config | mitigate | The dashboard stores NO credentials: DUCKDB_PATH is the only env var; the MT5 bridge is never reached from the web app (it reads marts + TOML only). Risk values render read-only. |
| T-04-05-02 | E (unauthenticated LAN exposure) | next start binding | mitigate | Hard-bind 127.0.0.1 in the start scripts (DASH-02, mirrors dashboard.py's loopback-only rule). Document that exposing it would reach the same data surface as the machine user. |
| T-04-05-03 | T (SQL injection via ?limit=) | /api/ledger route | mitigate | All queries are parameterized or use parsed-and-validated integers for LIMIT (coerce with Number + isFinite + clamp 1..1000). No user string ever reaches SQL text. |
| T-04-05-04 | I (write path to broker/risk) | API routes | mitigate | There are NO POST/PUT/DELETE routes by construction (DASH-02). The risk page renders values from TOML read-only; editing stays in tune_risk.py's warned CLI. Grep-verify: no order/position/risk mutation call exists in web/. |
| T-04-05-05 | D (warehouse absent/stale) | all routes/pages | mitigate | isWarehouseReady() gates every route (503 with a clear message) and every page (friendly empty state); /api/news is the deliberate exception — a missing mart_news_sentiment_daily (03-04 not run yet) returns 200 + [] because empty news is valid, not an outage. Stale marts render stale numbers but never crash; the RefreshButton + docs point to the reload commands. |
</threat_model>
